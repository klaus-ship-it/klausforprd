## 1. 名詞解釋

| 名詞 | 白話說明 |
|---|---|
| 終生累積 | 從玩家註冊那天起，儲值/流水金額一直累加，不會因為某個月沒消費就歸零或扣減 |
| 當月累積 | 每個月從 1 號重新開始計算，用來判斷這個月夠不夠格「保住」目前的等級 |
| 晉升 | 終生累積的儲值和流水都達到下一等級的門檻，等級往上調 |
| 保級 | 每月月底檢查「當月累積」是否達到目前等級要求的門檻，達到就維持等級 |
| 降級 | 保級檢查沒過，等級往下調一級 |
| 歷史最高等級 | 玩家有史以來達到過的最高等級，即使後來被降級，這個數字也不會往下修改。用來判斷「這是不是真的第一次達到這個等級」 |
| 保護期 | 玩家剛晉升的那個月，不用參加當月的保級檢查，下個月才開始正式計分 |

## 2. OPE-1002 VIP 階級配置

### 2.1 功能概述

本功能用於定義與維護全系統的 VIP 成長體系，共 16 個等級（VIP0～VIP15）。營運人員可在後台設定各等級的晉升門檻（儲值、流水）、保級門檻（月累計儲值、流水、活躍天數）、以及晉升時發放的一次性獎勵。

**這套機制的核心規則，一句話說明：**
玩家的終生累積儲值和流水**同時**達到某等級的門檻，才能晉升到該等級；晉升之後每個月都要重新達到「保級門檻」，沒達到就降一級；降級不會影響玩家已經累積的終生數據，未來重新達標一樣可以再升上去，但同一個等級的晉升獎勵一輩子只會拿到一次。

### 2.2 操作流程

**等級建立與編輯**

1. 管理員進入「VIP 等級設定」頁面，看到 VIP0～VIP15 的清單。
2. 點擊「編輯」修改等級名稱、圖示、頭像框、以及晉升/保級條件的說明文字（三語系：繁中/簡中/英文）。
3. 點擊「設定」修改實際的門檻數值與獎勵設定（僅限管理員操作，一般營運人員看不到這個按鈕）。
4. 儲存時系統會檢查「等級排序」是否重複、目前狀態是否為「啟用」，若重複則跳出錯誤提示，擋下這次儲存。
5. 每次修改都會自動記錄「最後修改時間」與「修改人員」。

**晉升觸發流程**

1. 系統持續追蹤每位玩家的終生累積儲值與終生累積流水。
2. 當玩家的終生累積數據同時達到某個等級的儲值門檻和流水門檻時，系統判定玩家達到晉升資格，將等級更新為新等級。
3. 若玩家一次儲值後同時跨過好幾個等級的門檻（例如從 VIP1 直接跳到 VIP4），系統會直接把等級設定到玩家實際可以達到的最高等級，並且把 VIP2、VIP3、VIP4 這三個等級「還沒領過」的晉升獎勵一次補齊發放（每個等級的獎勵一輩子只能領一次，見下方「防重複領獎」說明）。
4. 晉升當下，系統會：
   - 更新玩家「歷史最高等級」（如果新等級比原本紀錄的還高）
   - 給玩家一個月的「保護期」，這個月不用參加保級檢查
   - 發放這個等級的一次性升級獎勵

**保級與降級結算流程**

1. 每個月月底，系統對所有玩家做一次結算。
2. 如果玩家這個月處於「剛晉升的保護期」，這次結算跳過，不檢查，下個月才開始正式計分。
3. 如果玩家目前的等級是「無條件保級」等級（VIP0～VIP2），永遠不會被降級，跳過檢查。
4. 其餘等級：檢查玩家這個月的「累計儲值」「累計流水」「活躍天數」是否**同時**達到該等級的保級門檻：
   - 三項都達成：維持原等級
   - 任一項沒達成：降 1 級（不管差多少，固定只降 1 級，不會一次跌好幾級）
5. 降級**不會**影響玩家已經累積的終生儲值/流水數據，也不會抹除「歷史最高等級」的紀錄——這代表玩家之後只要終生數據重新達到門檻，還是可以再升回去，但同一個等級的晉升獎勵不會因為降級重升而再拿一次（防重複領獎機制，見下方）。
6. 結算完後，「當月累積數據」歸零，重新開始累計下個月的資料。

**手動調級流程（客服/管理員使用）**

1. 管理員在玩家詳情頁選擇「VIP 設定」，可以手動指定玩家的等級（0～15）。
2. **異動原因為必填欄位**，不填無法送出，這個原因會被寫入稽核日誌（見 OPE-1004）。
3. 管理員可以選擇「是否補發過往未領取的跨級升級獎勵」，預設為否。
4. 手動調整**不會**修改玩家真實的終生累積儲值/流水數據，只會更新目前等級和歷史最高等級（如果手動設定的等級比原本紀錄的歷史最高等級還高）。

**防重複領獎說明**

同一個等級的一次性升級獎勵，玩家一輩子只能領一次。判斷方式是：如果這次的新等級**沒有超過**玩家歷史上曾經達到過的最高等級，就不會再發獎勵。舉例：玩家曾經升到過 VIP3，後來被降到 VIP2，之後重新升回 VIP3，因為「歷史最高等級」已經是 3，這次不會再重複拿 VIP3 的獎勵。

### 2.5 邊界條件與例外處理

1. **跨級跳升**：玩家一次儲值後同時符合好幾級的門檻，系統直接把等級設到玩家能達到的最高一級，並補齊發放路徑上所有還沒領過的晉升獎勵。
2. **降級後回升不重複領獎**：玩家從 VIP3 降到 VIP2，之後重新升回 VIP3，因為歷史最高等級已經是 3，不會再拿一次 VIP3 的獎勵。
3. **手動調級不影響真實數據**：客服手動改玩家等級，不會動到玩家真實的終生累積儲值/流水，未來系統判斷是否自動晉升時，還是看玩家真實的消費數據。
4. **活躍天數定義**：需要「當天有登入」且「當天有實際投注」兩個條件都成立，才算一天活躍，避免玩家只是登入刷天數卻不玩。
5. **重複排序攔截**：後台已有一個等級用了排序值 1，管理員如果想把另一個等級也設成排序 1，系統會擋下這次儲存並提示「等級排序重複」。

### 2.6 驗收標準 (AC)

**AC-1：終生累積晉升與單次升級獎勵**
- 情境：玩家終生累計儲值與流水都達到 VIP5 門檻。
- 驗收：等級自動升至 VIP5，歷史最高等級更新為 5，玩家收到 VIP5 的升級獎勵。再次達標或儲值，不會重複收到 VIP5 獎勵。

**AC-2：保護期驗證**
- 情境：玩家在 1/15 晉升 VIP3。
- 驗收：1 月底結算時，因為在保護期內，不論當月消費多少都不會被降級，等級維持 VIP3。

**AC-3：降級後重升防迴圈**
- 情境：玩家終生累積已達 VIP5 門檻，但月保級沒過，被降到 VIP4（此時歷史最高等級仍為 5）。
- 驗收：次月玩家的等級**不會**自動跳回 VIP5（因為系統只看「當月是否達到保級門檻」而不是「終生數據是否還夠格」）。玩家要等到重新達到 VIP5 的**保級**門檻才會重升，而且重升時不會再拿一次 VIP5 的獎勵。

**AC-4：手動改級與過往獎勵補發**
- 情境：管理員把一個新註冊玩家（終生數據為 0）手動調整為 VIP3，並勾選「補發過往獎勵」。
- 驗收：玩家等級變為 VIP3，歷史最高等級變為 3，收到 VIP1、VIP2、VIP3 的一次性升級獎勵。之後玩家真實儲值達到 VIP4 門檻時，可以正常自動升級。

**AC-5：重複排序攔截**
- 情境：後台已有一個 VIP1 (排序 1) 為啟用狀態，管理員嘗試把另一個等級的排序也改成 1。
- 驗收：儲存時系統跳出「等級排序重複」提示，攔截這次儲存。

## 3. OPE-1003 VIP 統計分析

### 3.1 功能概述

提供 VIP 等級體系的健康度檢查，用圖表呈現各等級玩家的分佈比例，以及「升級、降級、留存」的變動率，作為營運調整 VIP 門檻與獎勵配置的參考依據。數據採**上個月完整結算**的方式呈現（本月看上個月的數據，不是即時數字）。

### 3.2 操作流程

1. 管理員進入「VIP 統計分析」頁面，預設顯示 4 個圓餅圖：左側是「全平台 VIP 分佈比例」，右側三個分別是留存率、降級率、升級率。
2. 點擊左側分佈圖裡的某個等級區塊（例如 VIP3），右側三個圖表會立即切換成「VIP3」這個等級上個月的變動數據。
3. 頁面上方會標示「數據結算至 YYYY/MM/DD」，讓使用者清楚知道這是哪個時間點的數據，不是即時的。
4. 頁面下方是一個等級清單，列出各等級的門檻簡述、狀態，點擊「編輯」可以直接跳轉到 VIP 等級設定頁面對應的編輯畫面。

### 3.3 統計指標定義

以「上個月月初」與「上個月月底」的玩家等級狀態做對比：

| 指標 | 計算方式 | 用途 |
|---|---|---|
| 當前分佈比例 | 該等級上月底人數 ÷ 全平台上月底 VIP 總人數 | 了解目前會員的等級組成 |
| 留存率 | (上月初是這個等級、月底還是這個等級的人數) ÷ 上月初這個等級的總人數 | 判斷這個等級的福利夠不夠吸引人留下來 |
| 降級率 | (上月初是這個等級、月底掉到更低等級的人數) ÷ 上月初這個等級的總人數 | 判斷保級門檻是不是設得太高 |
| 升級率 | (上月初是這個等級、月底升到更高等級的人數) ÷ 上月初這個等級的總人數 | 判斷晉升門檻是不是太容易或太難 |

### 3.4 邊界條件與例外處理

1. **新等級首月無數據**：如果某個等級是上個月才新增的，沒有「月初人數」可以比較，變動率圖表要顯示「無數據 (N/A)」，不能顯示 0% 或出現計算錯誤。
2. **分母為 0**：如果上個月月初該等級一個人都沒有，升級率/降級率/留存率統一顯示 0%，不能讓系統出錯。
3. **人工調整也算變動**：如果管理員手動改了玩家等級，這個變動一樣會計入升級率/降級率的統計，並且可以在 OPE-1004 稽核日誌裡查到細節。

### 3.5 驗收標準 (AC)

**AC-1：圖表連動**
- 情境：在分佈比例圖點擊「VIP5」。
- 驗收：右側三個圖表標題更新為「VIP5 變動分析」，數值也立即切換為 VIP5 的上月統計數據。

**AC-2：變動率計算**
- 情境：1/1 有 100 位玩家在 VIP3，到 1/31 結算時，50 人維持 VIP3、30 人降級、20 人升級。
- 驗收：2 月查看報表時，VIP3 留存率顯示 50%、降級率顯示 30%、升級率顯示 20%。

**AC-3：非即時數據標記**

- 驗收：頁面數據維持在 1/31 的結算結果，不包含 2/1～2/15 的變動，並清楚標示統計區間。

**AC-4：編輯跳轉**

- 驗收：正確跳轉到 VIP 等級設定頁面，並自動開啟該等級的編輯畫面。

## 4. OPE-1004 VIP 升降級稽核

### 4.1 功能概述

記錄所有玩家 VIP 等級變動的軌跡，包含自動晉升、月底自動降級、以及人工手動調整，是系統風控與稽核的核心紀錄。

### 4.2 操作流程

1. 系統每次有等級變動（不論自動或手動），都會產生一筆稽核紀錄。
2. 管理員可在「VIP 升降級稽核」頁面依玩家帳號搜尋，查看該玩家所有的歷史升降紀錄，依時間倒序排列。

### 4.3 稽核日誌欄位定義

| 欄位名稱 | 說明 |
|---|---|
| 紀錄 ID | 唯一流水號 |
| 玩家帳號 | 支援精確搜尋 |
| 原 VIP 等級 | 變動前的等級 |
| 新 VIP 等級 | 變動後的等級 |
| 動作類型 | 自動晉升 / 自動降級 / 保級成功 / 手動調整 |
| 觸發原因 | 條件達成 / 保級失敗 / 客服手動調整等文字說明 |
| 參考條件快照 | 記錄當下的儲值額、有效流水、活躍天數，供事後查核依據 |
| 是否補發跨級獎勵 | 僅手動調整時適用 |
| 操作人員 | 系統自動（SYSTEM）或管理員帳號 |
| 操作時間 | 變動發生的確切時間 |
| 備註 | 手動調整時的必填異動原因 |

### 4.4 獎勵發放規則

- **一次性升級獎勵**：判斷依據是「新等級是否超過歷史最高等級」，玩家確認/系統判定升級的當下即時發放。
- 常態性的週期獎勵（零用金、生日禮等）本輪未納入設計範圍，待之後另行討論。

### 4.5 邊界條件與例外處理

1. **手動調整後仍要參與後續判定**：管理員手動調整等級後，系統會自動更新「歷史最高等級」（如果新等級比較高），且下個月玩家仍然要正常參與保級判定。
2. **降級回升不重複領獎**：玩家 VIP3 降為 VIP2，再次升回 VIP3，因為 3 沒有超過歷史最高等級 3，不會再發一次首次獎勵。
3. **搜尋功能**：目前版本一次撈取所有紀錄，不限時間範圍，依時間倒序排列。

### 4.6 驗收標準 (AC)

**AC-1：升級紀錄與歷史最高等級更新**
- 情境：玩家達成 VIP2 晉升條件。
- 驗收：稽核日誌出現一筆「自動晉升」紀錄；玩家的歷史最高等級更新為 2。

**AC-2：保級成功紀錄**
- 情境：玩家在保級期間達成所有門檻。
- 驗收：稽核日誌出現一筆「保級成功」紀錄，等級維持不變。

**AC-3：降級紀錄**
- 情境：玩家保級未達標。
- 驗收：稽核日誌出現一筆「自動降級」紀錄，並附上當時未達標的數據快照；等級變更為原等級 -1。

**AC-4：首次獎勵唯一性**
- 情境：手動將一位玩家從 VIP1 調升至 VIP3。
- 驗收：玩家領取到 VIP2、VIP3 的升級獎勵；若後續降至 VIP2 再回升到 VIP3，不會再領取任何獎勵。

**AC-5：搜尋功能**
- 情境：在搜尋框輸入特定玩家帳號。
- 驗收：列表僅顯示該玩家的所有歷史升降紀錄，時間倒序排列。

## 5. 這次規格書與舊版的差異

給熟悉舊版 `VIP.md` 的人快速對照：

| 項目 | 舊版規格書 | 這次的新版 | 原因 |
|---|---|---|---|
| 特殊晉升條件（如綁定手機號碼） | VIP2 可用綁定手機號碼晉升，不用達到儲值/流水門檻 | 拿掉，所有等級一律只看儲值＋流水雙軌門檻 | 簡化判斷邏輯，避免特殊條件與雙軌門檻並存造成規則分支太多 |
| 週期性獎勵（零用金、生日禮、安慰金） | 舊版草稿有此設計 | 本輪不納入，只做一次性升級獎勵 | 先把核心晉升/保級迴路做完整，範圍不要一次鋪太大 |
| 等級門檻數值 | 兩個版本的數字都不一樣 | 全部重新用模型推導，兩版數字都不沿用 | 避免延續已經證實跟現有程式碼對不上的舊數字 |
| 保級緩衝機制 | 用「Retention 數值扣減」表示，較複雜 | 改用「布林保護期 + 固定降 1 級」，行為結果相同但更直觀 | 精簡設計，不影響玩家實際感受到的效果 |
